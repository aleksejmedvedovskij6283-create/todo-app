# Прецеденты приложения «Список дел»

Актёр: **Пользователь** — человек, который ведёт список дел через консольное меню.

## Прецедент «Добавить дело»
- Цель: зафиксировать новое дело в списке.
- Основной сценарий: пользователь выбирает пункт меню 1, вводит название и срок; дело появляется в списке, данные сохраняются.
- Альтернативный сценарий: название пустое — программа выводит сообщение об ошибке и повторяет ввод.

## Прецедент «Просмотреть список дел»
- Цель: увидеть все дела и их состояние.
- Основной сценарий: пользователь выбирает пункт меню 2; программа выводит дела с названием, сроком и статусом.
- Альтернативный сценарий: список пуст — программа выводит сообщение «Список дел пуст».

## Прецедент «Отметить дело выполненным»
- Цель: показать, что дело сделано.
- Основной сценарий: пользователь выбирает пункт меню 3 (например, из списка) и указывает название дела; статус меняется на «выполнено», данные сохраняются.
- Альтернативный сценарий: дела с таким названием нет — программа сообщает об этом и возвращает в меню.

## Прецедент «Удалить дело»
- Цель: убрать ненужное дело из списка.
- Основной сценарий: пользователь выбирает пункт меню 4 и указывает название дела; дело удаляется, данные сохраняются.
- Альтернативный сценарий: дела с таким названием нет — программа сообщает об этом и возвращает в меню.

## Прецедент «Сохранить данные» (служебный)
- Цель: не потерять список дел между запусками.
- Основной сценарий: после каждого изменения списка программа записывает все дела в файл.
- Альтернативный сценарий: файл недоступен для записи — программа сообщает об ошибке, список остаётся в памяти.

## Связи между прецедентами
- «Добавить дело», «Отметить дело выполненным», «Удалить дело» `<<include>>` «Сохранить данные» — после каждого изменения сохранение происходит всегда.
- «Отметить дело выполненным» `<<extend>>` «Просмотреть список дел» — отметку можно сделать прямо из списка (по условию).
- «Просмотреть список дел» с «Сохранить данные» не связан: просмотр данные не меняет.
